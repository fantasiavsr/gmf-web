Products API Service Layer

React fetch-based API client for Editorial Web backend

Phase 3 — Complete · Extended in Phase 6

Overview

The API service layer provides a clean interface for the React frontend to communicate with the Laravel backend's REST API. All functions use native fetch() and return promises.

🚀 Quick Start: Import API functions directly for products, or use src/services/data.js from dashboard components. The data layer now supports API-first CRUD with automatic mock fallback for products, services, and pricing plans.

API Configuration

config.js

Centralizes API settings and provides helper functions:

import { apiConfig, getApiEndpoint, handleApiResponse } from './config.js'

// Base URL determined by VITE_API_URL env var (defaults to http://localhost:8000/api)
console.log(apiConfig.baseUrl)

// Construct full endpoint URL
const url = getApiEndpoint('/products')  // → http://localhost:8000/api/products

// Handle responses (extracts JSON and throws on error)
const data = await handleApiResponse(response)

Environment Variables

Set in your local .env file (gitignored):

# .env (local development — create this file, it's gitignored)
VITE_DATA_SOURCE=api
VITE_API_URL=http://localhost:8000/api
VITE_API_TIMEOUT=1000

# Production (set in Vercel/hosting dashboard)
# VITE_API_URL=https://mydomain.com/api

Products API Endpoints

GET /products
Fetch all products
Returns
// Array of product objects
[
  {
    id: 1,
    name: "Wireless Headphones",
    type: "Electronics",
    sku: "WH-001",
    price: "$349",
    available: 24,
    status: "active",
    description: "Premium wireless headphones with noise cancellation.",
    created_at: "2026-09-14T06:23:52.000000Z",
    updated_at: "2026-09-14T06:23:52.000000Z"
  }
  // ...
]
Usage
import { getProducts } from './services/api/products.js'

const products = await getProducts()
GET /products/{id}
Fetch a single product by ID
Usage
import { getProduct } from './services/api/products.js'

const product = await getProduct(1)
POST /products
Create a new product
Usage
import { createProduct } from './services/api/products.js'

const newProduct = await createProduct({
  name: "Wireless Mouse",
  type: "Electronics",
  sku: "WM-007",
  price: "$39",
  available: 85,
  status: "active",
  description: "Ergonomic wireless mouse"
})
PUT /products/{id}
Update an existing product
Usage
import { updateProduct } from './services/api/products.js'

const updated = await updateProduct(1, {
  available: 15,
  price: "$299"
})
DELETE /products/{id}
Delete a product
Usage
import { deleteProduct } from './services/api/products.js'

const result = await deleteProduct(1)
// Response: { message: "Product deleted successfully" }

Error Handling

All API functions throw errors that can be caught with try/catch:

try {
  const products = await getProducts()
} catch (error) {
  console.error('Failed to fetch products:', error.message)
  // Handle error: show toast, retry, fallback to mock data, etc.
}

Testing the API Layer

A test file is included at src/services/api/test.js that verifies all endpoints work:

// In browser console or a test runner:
import { runApiTests } from './services/api/test.js'

await runApiTests()

The test suite will:

  • Fetch all products
  • Fetch a single product
  • Create a new product
  • Update the product
  • Delete the product
  • Report success or failure for each step

Architecture

React Component
       ↓
  Data Abstraction (src/services/data.js)
       ↓
  ┌─────────────────────────────────┐
  │ Try API first (with timeout)    │
  │         ↓                       │
  │   fetch() to Laravel API        │
  │         ↓                       │
  │  Success? → Return API data     │
  │  Failed?  → Fallback to mock    │
  └─────────────────────────────────┘

The data abstraction layer (Phase 4) handles fallback automatically. Components just call productDataSource.getAll() and get data regardless of which source is active.
