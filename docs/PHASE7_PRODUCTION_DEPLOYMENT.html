Production Deployment Guide

Phase 7 · Prepare Laravel + MySQL and Vercel without committing secrets or deploying from the repository.

What Phase 7 completed

Production configuration is documented, not deployed.

This phase adds CORS configuration, safe environment templates, deployment instructions, and frontend hosting guidance. Production domain, database credentials, HTTPS, and reverse-proxy rules remain operator-owned values.

Backend environment

Copy the server template into the server's private .env. Never commit it.

APP_ENV=production
APP_DEBUG=false
APP_URL=https://api.example.com
APP_KEY=<generate privately on server>

DB_CONNECTION=mysql
DB_HOST=<production database host>
DB_PORT=3306
DB_DATABASE=editorial_backend_prod
DB_USERNAME=editorial_backend
DB_PASSWORD=<private password>

FRONTEND_URL=https://www.example.com
LOG_LEVEL=error
Do not use local values in production.

Use a dedicated MySQL user, not root. Do not expose passwords, APP_KEY, or private credentials in React or Vite variables.

Laravel deployment sequence

  1. Provision PHP 8.2+, Composer, MySQL, and HTTPS.
  2. Clone editorial-backend; point the web-server document root to public/.
  3. Create the private .env and generate the key on the server.
  4. Install and migrate safely:
composer install --no-dev --optimize-autoloader
php artisan key:generate
php artisan migrate --force
php artisan config:cache
php artisan route:cache
php artisan view:cache
php artisan storage:link

Do not run migrate:fresh or destructive seed commands against production.

CORS and browser origins

The API reads FRONTEND_URL and applies it to /api/*. Credentials are disabled because authentication is not in scope. Keep the origin exact; do not use a wildcard for a production API.

Frontend origin: https://www.example.com
API origin:      https://api.example.com/api

Same-domain hosting still requires a reverse proxy: DNS alone does not route /api/* to Laravel.

Vercel frontend modes

Mock/demo mode

Do not configure Vite API variables in Vercel. With no .env, the app defaults to mock data and remains independent of Laravel.

Production API mode

Set these as Vercel project environment variables, not committed files:

VITE_DATA_SOURCE=api
VITE_API_URL=https://api.example.com/api
VITE_API_TIMEOUT=5000

All VITE_ values are public and must contain no secrets.

SPA routing

React routes such as /dashboard need an SPA fallback to /index.html. Laravel API routes must remain separate under /api/* and must not be swallowed by the frontend fallback.

Verification checklist

  • php artisan test
  • php artisan route:list --path=api
  • curl https://api.example.com/api/health
  • Check CORS headers from the real frontend origin
  • Build the frontend with no local .env to verify mock fallback
  • Test API mode from Vercel only after the production API and HTTPS are ready
