Mock/API Switching Architecture

Phase 4 — The major architectural checkpoint

Complete & Verified

Overview

Phase 4 implements the abstraction layer that allows the React frontend to seamlessly switch between mock data (for development and Vercel deployment) and real API calls (for production). This is the critical architectural checkpoint where the two deployment modes converge.

🎯 The Key Insight: React components use a single unified interface. The underlying data source (mock or API) is controlled by environment variables — components don't need to know or care which one is active.

The Two Deployment Modes

MOCK Vercel / Demo
  • Uses local mock data
  • No backend required
  • Works offline
  • Instant responses
  • Perfect for demos
  • Automatic: No .env on Vercel = mock mode
API Local Dev / Production
  • Uses Laravel API
  • Queries MySQL database
  • Real CRUD operations
  • Network requests
  • Persisted data
  • Automatic: API first, fallback to mock if backend down
🎯 Single Configuration: No need to switch between files. The same codebase automatically handles both modes:
  • Vercel: No .env → defaults to mock → works without backend
  • Local dev: Create .env → tries API → falls back to mock if backend down
  • Production: Set VITE_API_URL in hosting dashboard → uses real API

The Abstraction Layer

Located in src/services/data.js, the abstraction layer provides a single interface for components:

import { productDataSource } from './services/data.js'

// Same interface, any data source
const products = await productDataSource.getAll()
const product = await productDataSource.getById(1)
await productDataSource.create(newProduct)
await productDataSource.update(id, changes)
await productDataSource.delete(id)

How It Works

At runtime, the data service always tries the API first, then falls back to mock if anything fails:

React Component ↓ productDataSource.getAll()
Check: VITE_DATA_SOURCE === 'api'?
✓ YES → Try API ↓ fetch() with timeout
Success → Return API data
Failed/Timeout → Fallback to mock

API mode tries real fetch() with a configurable timeout. If it fails or times out, automatic fallback kicks in and uses mock data. No errors shown to the user.

Key Architecture Features

✓ Single Configuration

No need to switch between .env files. The same codebase automatically handles both modes.

✓ API with Fallback

Tries API first with configurable timeout. Falls back to mock automatically if backend is down.

✓ Loading States

Dashboard shows spinner while loading, error message if something fails, with manual retry option.

✓ Configurable Timeout

Set VITE_API_TIMEOUT in .env (default: 1000ms). Controls how long to wait before fallback.

✓ Vercel Ready

.env is gitignored. Vercel automatically uses mock mode without any configuration.

Data Flow

API Mode (Default)

React Component
    ↓
productDataSource.getAll()
    ↓
Tries: fetch('http://localhost:8000/api/products')
    ↓
┌─ Success? → Return API data (real database)
└─ Failed?  → Fallback to mock data (no error shown)

Mock Mode (Vercel)

React Component
    ↓
productDataSource.getAll()
    ↓
VITE_DATA_SOURCE is undefined → defaults to 'mock'
    ↓
Return MockProducts array (no fetch needed)
    ↓
Component renders products
