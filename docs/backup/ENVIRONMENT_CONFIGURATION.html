Environment Configuration Guide

Understanding Vite environment variables and mock/API switching

The Issue: Why Your Backend Isn't Always Required

🔴 Critical Discovery: Vite loads environment files in priority order. .env.local always overrides .env. This means your dev server may be in API mode even when you thought it was in mock mode.

When you turn off XAMPP or stop running php artisan serve, the dashboard still loads because of intelligent API fallback to mock data. This is now a feature (after the fix), but it's important to understand the environment configuration to properly test both modes.

Vite Environment Variable Precedence

Vite loads environment files in this order (highest to lowest priority):

.env.local ← ✅ Highest priority (loaded first, overrides everything)
.env ← Fallback (used if .env.local doesn't exist)
📌 How Vite Works: When the dev server starts, it reads environment variables ONCE. Changes to .env files require restarting npm run dev to take effect. The values are cached and baked into the client at build time.

Current Configuration

MOCK .env 
VITE_DATA_SOURCE=mock

Default. Used for Vercel deployment and demo mode.

API .env.local 
VITE_DATA_SOURCE=api
VITE_API_URL=http://localhost:8000/api

Local development. Overrides .env if it exists.

⚠️ Your Current Setup: Since .env.local exists, your dev server is currently in API mode. Even though .env says mock, .env.local takes precedence.

How to Switch Modes

Option 1: Use Mock Mode (For Vercel/Demo)

  1. Delete or rename .env.local
  2. Restart dev server: npm run dev
  3. Dev server now reads .env which says VITE_DATA_SOURCE=mock
  4. No backend required — dashboard works offline
$ rm .env.local
$ npm run dev
# Output in console: 📦 Data source: MOCK

Option 2: Use API Mode (For Local Development)

  1. Keep .env.local in place
  2. Start Laravel backend: php artisan serve --port=8000
  3. Restart dev server: npm run dev
  4. Dev server reads .env.local which says VITE_DATA_SOURCE=api
  5. Dashboard fetches real data from API
$ php artisan serve --port=8000
# In another terminal:
$ npm run dev
# Output in console: 📦 Data source: API

Intelligent API Fallback (New!)

When API mode is enabled but the backend is unavailable, the system now gracefully falls back to mock data:

API Request → FAILED (backend down)
    ↓
Check: ENABLE_API_FALLBACK = true?
    ↓
YES → Use mock data instead
    ↓
⚠️  Console warning: "API request failed, falling back to mock data"
    ↓
Dashboard displays mock products normally

This is why your dashboard still works even when XAMPP is off — it falls back gracefully instead of showing an error.

Debugging: Check Your Current Mode

🔍 Check Console Output
Open browser DevTools → Console tab
Look for these messages on page load:
✓ Mock mode: 📦 Data source: MOCK
✓ API mode: 📦 Data source: API
⚠️ Fallback active: ⚠️ API request failed, falling back to mock data

Quick File Check

$ cat .env
VITE_DATA_SOURCE=mock

$ cat .env.local
VITE_DATA_SOURCE=api
VITE_API_URL=http://localhost:8000/api

If both files exist: .env.local wins (API mode)

If only .env exists: Mock mode is active

Testing Checklist

✓ Test Mock Mode

  1. Delete/rename .env.local
  2. Restart: npm run dev
  3. Open dashboard: http://localhost:5173/dashboard/products
  4. Verify: Shows 6 products
  5. Console: 📦 Data source: MOCK
  6. Turn off XAMPP and Laravel — dashboard still works

✓ Test API Mode (Backend Running)

  1. Start Laravel: php artisan serve --port=8000
  2. Restart: npm run dev
  3. Open dashboard: http://localhost:5173/dashboard/products
  4. Verify: Shows 6 products from API
  5. Console: 📦 Data source: API
  6. Try CRUD operations: create/edit/delete persists in MySQL

✓ Test API Fallback (Backend Off)

  1. Start in API mode (with .env.local)
  2. Turn off XAMPP or stop Laravel
  3. Refresh dashboard
  4. Verify: Still shows 6 products (from fallback)
  5. Console: ⚠️ API request failed, falling back to mock data

Key Takeaways

  • 📌 .env.local overrides .env — It's not a mistake, it's intentional design
  • 🔄 Changes require restart — Vite caches env variables at startup
  • 🎯 Two modes, one codebase — Same React app works in both
  • ⚡ Graceful fallback — API mode falls back to mock if backend fails
  • ✅ Vercel uses .env — Automatically uses mock mode (no backend needed)
