Role-Based Routing System IMPLEMENTED

This document describes the role-based routing system implemented for the Editorial Web project. Users are now routed to different dashboards based on their assigned role.

Overview

The role-based routing system ensures that:

  • Users with role "admin" access the admin dashboard (/dashboard)
  • Users with role "user" access the user dashboard (/user-dashboard)
  • Unauthenticated users are redirected to /login
  • Users attempting to access routes outside their role are redirected to their allowed dashboard

Components

1. RoleBasedRoute Component

Location: src/components/RoleBasedRoute.jsx

A React component that wraps route groups and enforces role-based access control.

import { Navigate, Outlet } from "react-router-dom"; import { useAuth } from "../context/AuthContext"; export default function RoleBasedRoute({ requiredRole }) { const { isAuthenticated, loading, user } = useAuth(); if (loading) return null; if (!isAuthenticated) return <Navigate to="/login" replace />; if (requiredRole && user?.role !== requiredRole) { if (user?.role === "admin") return <Navigate to="/dashboard" replace />; if (user?.role === "user") return <Navigate to="/user-dashboard" replace />; return <Navigate to="/unauthorized" replace />; } return <Outlet />; }
How it works:
  • Checks if user is authenticated via AuthContext
  • Verifies user has the required role
  • Redirects to appropriate dashboard if role doesn't match
  • Renders nested routes if all checks pass

User Flow

Login Flow

User navigates to /login
Enters credentials and submits
Backend validates and returns user with role
Frontend stores token and user role in AuthContext
User is redirected based on role:
  • Admin → /dashboard
  • User → /user-dashboard

Access Control Flow

User tries to access a protected route
RoleBasedRoute component checks authentication
RoleBasedRoute checks required role
If role matches → Route is accessible
If role doesn't match → Redirect to allowed dashboard

Implementation Details

AuthContext Integration

The RoleBasedRoute component uses the AuthContext to access:

  • isAuthenticated - Whether user is logged in
  • user.role - The user's assigned role
  • loading - Whether auth state is still being validated
Important: The user role comes from the backend during login and is never modified by the frontend. This ensures role-based access control cannot be bypassed by client-side manipulation.

Backend Integration

The backend provides user roles through:

  • POST /api/login - Returns user object with role
  • GET /api/user - Returns authenticated user with role
  • POST /api/register - New users assigned default role "user"

Security Considerations

⚠️ Important:
  • Role is determined by backend and sent during authentication
  • Frontend enforces UI-level access control
  • Backend API endpoints are also protected with authentication middleware
  • CRUD operations (products, services, pricing) require valid authentication token
  • Even if frontend is bypassed, backend API will reject unauthorized requests
